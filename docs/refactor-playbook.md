# 테스트·코드 품질 리팩터링 방식 (프로 방식 메모)

> 2026-11-28 Anisched 리팩터링 라운드에서 쓴 기준과 순서. **다른 프로젝트(Anicel 등)에 그대로 옮겨 쓰려고** 앱에 묶이지 않게 적는다.
> 이번 라운드의 실제 기록은 `testing.md`(데이터 쪽) · `testing-ui.md`(화면 쪽).

## 참고한 기준 4개

| 출처 | 가져온 것 |
|---|---|
| **Vladimir Khorikov, 『Unit Testing: Principles, Practices, and Patterns』** | 좋은 테스트의 **4기둥** — ①회귀 보호(버그를 잡나) ②리팩터링 내성(구현을 바꿔도 안 깨지나) ③빠른 피드백 ④유지보수성. 넷 중 ②가 가장 자주 무너진다. **관찰 가능한 동작만** 보고 구현 세부(내부 SQL 문자열 · private 호출 순서 · 호출 횟수)를 핀하지 않는다. **대역(mock)은 관리되지 않는 의존**(사용자 파일 · 플랫폼 채널 · 외부 서비스)에만 — 앱만 쓰는 DB 는 실물(메모리 DB)로. |
| **Google, 『Software Engineering at Google』 (테스트 장)** | **동작을 테스트, 구현이 아니라**. 테스트 크기(작음/중간/큼)를 나누고 **작은 테스트가 중심**. 테스트 코드는 **DAMP(설명적으로 반복) > DRY** — 헬퍼로 숨겨서 읽기 어려워지면 손해. |
| **Kent Beck, Test Desiderata** | 테스트끼리 **독립**, 결과가 **결정적**(매번 같음), **읽히는** 이름. |
| **Anicel 에서 정한 규칙** | ①**한 법은 가장 싼 층에서 한 번만 핀**(같은 법을 위젯·로직·통합에서 각각 확인 = 중복). ②**「통과는 증거가 아니다 — 제품 코드를 끄면 빨개지는지가 증거」** ⇒ 뮤테이션. ③복잡도는 **인지 복잡도 15 를 경고선**(게이트 아님, 이해가 나빠지는 분할 금지). ④**결정 주석(누가 왜 정했나)은 지우지 않는다.** ⑤사본은 3의 규칙(세 번째가 나오기 전엔 합치지 않음). |

## 순서

1. **테스트 감사 — 파일·테스트마다 「무엇을 지키나」 한 줄**
   - 같은 법을 두 곳 이상에서 핀하면 **가장 싼 층 하나만** 남긴다(예: 「백그라운드 리더가 스토어와 같은 답」을 기능마다 다시 보던 것 → 리더 대조 테스트 한 곳, 실제 isolate 로).
   - 구현 세부를 핀하는 테스트(위젯 트리 모양 · 내부 순서) → 동작 테스트로 바꾸거나 삭제.
   - 위젯(화면) 테스트가 **판단**까지 확인하고 있으면 판단을 순수 함수/컨트롤러로 빼고, 판단은 거기서 · 위젯은 「묻고 보여 준다」만.
   - 큰 조합 행렬(언어 × 화면 크기 × 모든 탭)은 **위험한 조합만**(긴 단어 × 좁은/낮은 화면). 넘침 같은 건 어느 위젯 테스트든 자기 크기에서 잡는다.
   - **가장 느린 20개**를 재고, 느린 이유가 법이 아니면(데이터 양 · 준비 비용) 줄인다.
2. **손 뮤테이션 — 핵심 로직만**
   - 뮤턴트: 조건 뒤집기 · 경계 ±1(`<` ↔ `<=`) · 리턴값 바꾸기 · 조건 하나 빼기.
   - 살아남은 뮤턴트 = 테스트 빈틈 → **그 경계를 순수 함수 층에서 한 번** 핀하고 다시 돌린다.
   - 결과가 같은 **동등 뮤턴트**는 표에 「동등」 사유와 함께 남긴다. 그게 실제로 안 쓰이는 조건이면 **죽은 코드로 삭제**.
   - 🚨**뮤테이션은 커밋한 뒤에**, 되돌리기는 **`cp` 왕복**(`git checkout` 금지 — 미커밋 작업을 날린 사고가 있었다).
3. **코드**
   - 같은 알고리즘이 두 벌 이상 → 합치기(3의 규칙). 판정은 이름이 아니라 **하는 일**이 같은지로.
   - 인지 복잡도 15 초과 목록을 **경고로** 뽑고, 읽기 좋아질 때만 나눈다.
   - 죽은 코드 · 안 쓰는 API · 안 쓰는 문자열 키 삭제. 결정 주석은 남긴다.
4. **구조 래칫** — 의존 방향(안쪽 층이 바깥 층·위젯을 import 하지 않음)을 **테스트로 자동 검사**, 예외 장부 0 으로 시작. 그 테스트가 **일부러 심은 잘못된 import 를 잡는지**도 확인(검사기가 조용히 아무것도 안 하는 일 방지).

## 보고 꼴

- 테스트 수 · 실행 시간 **전/후**
- 지운/옮긴 테스트와 **이유**(표)
- 뮤턴트: 총수 · 1차 생존 · 처리(보강/동등/삭제) · 2차 생존
- 복잡도 15 초과 목록과 판단(나눔/유지 + 이유)
