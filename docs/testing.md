# 테스트 원칙과 감사 기록 (데이터 쪽: core · models · services · platform · controllers)

## 기준

- **Khorikov 『Unit Testing Principles』의 4기둥** — 회귀 보호 · 리팩터링 내성 · 빠른 피드백 · 유지보수성.
  구현 세부(내부 SQL 문자열 · private 순서 · 호출 횟수)를 핀하지 않고 **관찰 가능한 동작**을 본다.
  대역은 **관리되지 않는 의존**(사용자 파일 · 플랫폼 채널)에만. SQLite 는 관리되는 의존이라 실DB(메모리/임시 파일) 그대로.
  채널 테스트(`document_channel_test`)가 메서드 이름·인자를 확인하는 것은 네이티브와의 **계약**이라 예외가 아니다.
- **Google SWE Book** — 동작을 테스트, DAMP(읽히게) > DRY, 작은 테스트 중심.
- **Anicel 규칙** — 한 법은 **가장 싼 층에서 한 번만** 핀(중복 핀 금지). 「통과는 증거가 아니다 — 제품 코드를 끄면
  빨개지는지가 증거」 ⇒ 손 뮤턴트로 확인(아래). 뮤테이션은 커밋 뒤에, 되돌리기는 `cp` 왕복(`git checkout` 금지).
