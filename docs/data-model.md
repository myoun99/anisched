# 데이터 모델 초안 (제안 — 확정 아님)

> 데이터 담당 초안. **❓ 표시는 유저가 정할 것**이고, 답이 오기 전에는 스키마에 넣지 않는다.
> 지금 구현된 것은 스키마 버전 뼈대와 `work_intervals`(타이머 구간) 뿐이다.

## 저장 원칙 (기술 결정 — 담당이 정함)

- 시각은 **UTC epoch 밀리초 INTEGER**. 화면에서만 로컬 시간으로 바꾼다.
- 돈은 **정수 최소 단위**(원 → 원, 엔 → 엔). 실수(float) 금지. 통화 코드는 별도 컬럼.
- 경과 시간은 **저장하지 않는다**. 타이머는 시작·정지 시각만 저장하고 경과는 계산.
  앱을 죽였다 켜도 `stopped_at IS NULL` 인 행이 그대로 남아 있으므로 정확하다.
- 스키마 버전은 `PRAGMA user_version`. 마이그레이션은 앞으로만, 한 단계 = 한 트랜잭션.
  이미 배포된 단계는 고치지 않고 새 단계를 추가한다. 더 새 버전 파일은 열기를 거부.
- 삭제는 기본 **소프트 삭제**(`archived_at`) 제안 — 정산 기록이 사라지면 안 되므로.
- 금액·단가는 청구 시점에 **스냅샷**을 남긴다(나중에 단가를 고쳐도 지난 청구서가 바뀌지 않게).

## 엔티티 초안

```
작품 work ─┬─< 화수 episode ─┬─< 컷 cut ─┬─< 공정 작업 cut_task (공정·상태·마감·단가)
           │                 │           └─< 리테이크 retake ❓
           │                 └─ 마감(화 단위) ❓
           └─ 거래처 client ❓

청구 invoice ─< 청구 항목 invoice_line ─> cut_task (단가 스냅샷)
입금 payment ─> invoice (부분 입금 ❓)

작업시간 work_interval ─> (연결 대상 ❓: 컷 / 화 / 작품 / 없음)
```

| 엔티티 | 주요 필드(초안) | 비고 |
|---|---|---|
| work 작품 | id, 제목, 거래처(제작사)?, 색, archived_at | |
| episode 화수 | id, work_id, 화 번호(텍스트: "#05", "OP" 등), 마감? | 번호를 정수로 할지 ❓ |
| cut 컷 | id, episode_id, 컷 번호(텍스트: "C012", "C012A"), 메모, 난이도/초수? | 겸용컷·뱅크 ❓ |
| cut_task 공정 작업 | id, cut_id, 공정, 상태, 받은 날, 마감, 완료일, 단가, 수량 | "한 컷 × 한 공정" = 정산 단위 |
| retake 리테이크 | id, cut_task_id, 받은 날, 마감, 완료일, 유료 여부·단가 | ❓ |
| invoice 청구 | id, 거래처, 기간, 발행일, 통화, 합계(스냅샷) | |
| invoice_line | id, invoice_id, cut_task_id, 단가 스냅샷, 수량 | |
| payment 입금 | id, invoice_id, 입금일, 금액, 원천징수? | ❓ |
| work_interval 작업시간 | id, started_at, stopped_at (구현됨) | 연결 대상은 질문 후 컬럼 추가 |

## 질문 목록

### A. 유저가 정할 것 (도메인)

1. **공정 단계 이름과 순서** — 예: 레이아웃(LO) / 원화 1원 / 2원 / 작감 수정 / 동화 …
   - 선택지: ① 고정 목록 ② 고정 기본값 + 유저가 추가·이름변경 ③ 완전 자유
   - 추천: ② (기본값 제공, 편집 가능)
2. **상태 단계** — 예: 받음 → 작업중 → 제출 → 리테이크 → 완료(OK)
   - 선택지: ① 위 5단계 고정 ② 공정마다 다름 ③ 유저 정의
   - 추천: ① 으로 시작
3. **컷 단가가 공정마다 다른가** (LO·원화·2원 단가가 따로인지, "LO+원화" 묶음 단가인지)
   - 선택지: ① 공정별 단가 ② 컷당 하나 ③ 둘 다(묶음 공정 허용)
   - 추천: ① 공정별 (묶음은 "LO+원화"라는 공정 하나로 표현)
4. **단가의 기본값은 어디서 오나** — 작품별 / 거래처별 / 화별 / 컷마다 직접
   - 추천: 작품별 공정 기본 단가 → 컷에서 덮어쓰기 가능
5. **리테이크(수정) 단가** — ① 무료 ② 유료(고정액) ③ 유료(원 단가의 %) ④ 건마다 다름
   - 추천: 기본 무료, 건별로 "유료" 체크 시 금액 입력 (④의 단순형)
6. **작감 수정 컷**은 별도 공정인가, 리테이크와 같은 개념인가? (나에게 오는 "수정 몇 컷")
   - 추천 없음 — 실제 흐름을 들어야 함
7. **컷 외 정산 단위** — 초 단위·장수 단위·시급·고정 일당이 있는가?
   - 추천: 수량 필드를 두고 단위(컷/초/장/시간) 선택
8. **통화** — ① 원화만 ② 엔화 포함(일본 작품) ③ 작품마다 통화
   - 추천: ③ (작품에 통화 지정, 합산은 통화별)
9. **원천징수(3.3%)·세금** 처리 — 입금액에서 공제해 기록할지, 청구액만 기록할지
   - 추천: 청구액 + 공제율 필드, 실입금액은 계산
10. **월 정산 마감일** — ① 말일 ② 거래처마다 다름(예: 20일 마감) ③ 청구 단위로 자유
    - 추천: 거래처별 마감일, 기본 말일
11. **부분 입금**이 있는가 (한 청구서에 입금 여러 번)
    - 추천: 허용(입금 여러 행)
12. **마감 단위** — 컷마다 / 화마다 / 둘 다
    - 추천: 화 마감 기본 + 컷별 덮어쓰기
13. **컷 번호 형식** — 겸용컷("C012-014"), 분할("C012A"), 뱅크컷 처리
    - 추천: 텍스트로 저장, 정렬용 숫자 키는 자동 추출
14. **작업시간은 무엇에 붙나** — ① 컷 공정 ② 화 ③ 작품 ④ 아무것도 안 붙여도 됨
    - 추천: 컷 공정에 붙이되 비워도 됨(nullable)
15. **타이머 동시 실행** — 한 번에 하나만 / 여러 개
    - 추천: 하나만 (현재 임시 구현이 이 규칙)
16. **"하루"의 경계** — 자정 / 새벽 N시 (밤샘 작업을 전날로 칠지)
    - 추천: 설정값, 기본 새벽 5시

### B. 담당이 정하는 것 (기술 — 이견 있으면 알려 주면 됨)

- UTC 밀리초 저장, 금액 정수, 통화 코드 컬럼
- `user_version` 기반 전진 마이그레이션, 단계별 트랜잭션, 새 버전 파일 거부
- 소프트 삭제, 청구 시점 단가 스냅샷
- 시계가 뒤로 간 경우 경과 0 으로 처리(음수 금지)
- 기기 시계를 바꾸면 실행 중 타이머 경과도 바뀐다(벽시계 기준) — 단조 시계는 재시작을 못 넘기므로 의도적 선택
