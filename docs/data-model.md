# 데이터 모델

> 데이터 담당. 유저 답 6차까지 반영 → 스키마 v7 + 보기용 쿼리. **❓ = 아직 유저 답이 필요한 것.**

## 저장 원칙 (기술 결정)

- 시각은 **UTC epoch 밀리초 INTEGER**. 예외: 쉬는 날(`days_off`)은 하루 단위라 **현지 날짜 텍스트 `YYYY-MM-DD`**(시간대가 바뀌어도 날이 밀리지 않게).
- 마감도 날짜가 아니라 시각으로 저장(화면이 날짜로 보여 줌).
- 돈은 **정수 최소 단위**(엔·원 모두 소수 없음). 통화는 작품에 3글자 코드, 기본 `JPY`.
- 경과 시간은 저장하지 않는다 — 타이머는 시작·정지 시각만, 경과는 계산.
- 스키마 버전 = `PRAGMA user_version`. 앞으로만, 한 단계 = 한 트랜잭션, 더 새 파일은 거부.
- 삭제는 **소프트 삭제**(`archived_at`).

## 설정 (`settings` 테이블, 키 하나 = 행 하나, 없으면 기본값)

| 키 | 뜻 | 기본 |
|---|---|---|
| `seconds_rounding` | 초당 단가에서 컷 길이를 초로 맞추는 방식 — **작품마다 덮어쓸 수 있음**(`works.seconds_rounding`, NULL=앱 설정) | `nearest`(반올림) |
| `day_start_minutes` | 하루가 시작하는 시각(자정 뒤 분) | `0`(자정) |
| `rest_weekdays` | 쉬는 요일(1=월 … 7=일), 하루 몇 컷 계산에서 뺌. 빈 값 = 매일 일함 | **토·일** |
| `pace_end` | 하루 몇 컷의 끝: `plan`(내 계획 끝 → 없으면 마감) / `due`(제작 마감) | `plan` |

**초당 단가 반올림은 「길이」에 적용한다** — 길이를 먼저 정수 초로 맞추고 단가를 곱한다.
- `nearest` 반올림: 3.5초 → 4초, 3.49초 → 3초
- `up` 올림: 3.01초 → 4초
- `down` 버림: 3.99초 → 3초
- `exact` 비례: 3.5초 그대로 → 금액만 엔 단위로 반올림
(유저: 실제 업계 방식은 나중에 확인 — 그래서 옵션.)

## 구조 (v7)

```
공정 프리셋 stage_presets → stage_preset_items (여러 개, 이름·목록 편집, 기본은 정확히 하나)
   작품 등록 때 프리셋을 골라 복사(안 고르면 기본) → 이후 프리셋을 고치거나 지워도 기존 작품은 안 바뀜
   기본 프리셋은 지울 수 없음 — 다른 것을 기본으로 바꾼 뒤 지움

거래처 clients (마감일, NULL=말일)
 └< 작품 works (통화 기본 JPY, 반올림 덮어쓰기, 기본 단가 방식 default_rate_unit — 화 단가 입력 때 미리 선택)
     ├< 공정 목록 work_stages (작품마다 편집 가능, 순서 있음 — 만들 때 프리셋에서 복사)
     └< 화수 episodes
         ├< 화수별 기본 단가 episode_rates (공정마다: 고정액 / 초당)
         ├< 담당 파트 parts (라벨 「B」, 예정 컷 수 — 컷 목록보다 먼저 적을 수 있음)
         │    ├< 파트 × 공정 마감 part_stage_dues      (제작 마감)
         │    └< 파트 × 공정 내 계획 part_stage_plans  (시작 예정 · 끝낼 예정, 둘 중 하나만도 됨)
         ├< 컷 cuts (번호 텍스트 + 자동 정렬 키, 길이 length_ms, 소속 파트 part_id — 없어도 됨)
         └< 콘티 storyboards (컷이 아닌 하나의 단위)

내 작업 tasks = (공정 1개) × (컷 1개 또는 콘티 1개)
   상태: 받음 → 작업중 → 제출 → 리테이크 → 완료
   마감: 작업에 직접 넣은 마감 → 없으면 그 컷이 속한 파트의 그 공정 마감 (뷰 task_dues)
   내 계획: 작업 plan_start_at / plan_end_at → 없으면 파트 계획 (칸마다 따로 덮어씀)
   단가 덮어쓰기(rate_unit, rate_amount)
 ├< 리테이크 retakes (테이크 2, 3, … 제한 없음, 기본 무료, 건별 유료 + 금액)
 └< 작업시간 work_intervals.task_id (비워도 됨, 타이머는 한 번에 하나)

쉬는 날 days_off (단일 날짜 또는 기간, 메모 — 여행·병원 등)
```

처음 기본 프리셋 10개: 콘티 · 콘티 체크 · LO · LO 연출 수정 · LO 작감 수정 · LO 총작감 수정 ·
원화 · 원화 연출 수정 · 원화 작감 수정 · 원화 총작감 수정.
유저 역할(원화맨 / 작감 / 연출)은 따로 저장하지 않고, **어느 공정에 내 작업이 있는가**로 드러난다.

### 담당 파트 흐름

1. 파트를 만든다 — 「작품 A · #05 · B파트 · 11컷」(컷 목록은 나중이어도 됨).
2. 파트에 공정 마감을 넣는다 — 「B파트 LO 12/10까지」.
3. 컷이 들어오면 파트에 넣고 `addTasksForPart` 로 그 공정의 작업을 한 번에 만든다.
4. 컷 작업은 기본으로 파트 마감을 따른다. 파트 마감을 옮기면 따라 움직인다.
   컷에 직접 마감을 넣으면 그 컷만 따로 간다(옵션 — 세세한 수정).

### 단가 · 합계

- 단가 방식은 작품에 따라 **공정별 컷당**(기본) 또는 **공정별 초당**. 한 컷에 둘이 더해지지는 않는다.
  공정별 기본 금액은 앱이 박아 두지 않는다(유저가 화수마다 입력).
- 작업의 단가 = 작업에 직접 넣은 단가(`setTaskRate`, 컷 × 공정마다) → 없으면 그 화수의 그 공정 기본 단가
  → 없으면 미정. 유저: 화 단위 유지 + 컷마다 다를 수 있음 → 이 덮어쓰기로 충분.
- 작업 금액 = 단가 금액 + 유료 리테이크 금액 합.
- **월 합계 = 완료일 기준, 통화별 따로(환산 없음).** 거래처 마감일로 기간을 자른다
  (20일 마감이면 전월 21일 ~ 당월 20일, 거래처 없으면 달력 한 달). 단가·길이가 없어
  계산 못 한 작업은 「미정 n건」으로 따로 센다.
- 청구·입금 테이블은 없다(유저: 금융 앱 아님, 합계만).

## 두 축 일정 — 제작 마감 vs 내 계획

| 축 | 누가 정하나 | 저장 | 비슷한 개념 |
|---|---|---|---|
| **제작 마감** `dueAt` | 제작진행 | 파트 × 공정 + 컷 덮어쓰기 | Todoist *deadline*, OmniFocus *due*, MS Project *Deadline* |
| **내 계획** `planStartAt` · `planEndAt` | 나 | 같은 패턴(파트 × 공정 + 컷 덮어쓰기) | Todoist *date*(언제 할지), OmniFocus *defer*(그 전엔 회색), MS Project *Start/Finish*(일정) |

- 근거: 세 도구 모두 「바깥에서 정한 끝」과 「내가 정한 일정」을 다른 필드로 두고, 마감이 지나면 계획과 상관없이 지연으로 본다
  (OmniFocus: 지연은 defer 와 무관하게 지연 표시. MS Project: 일정이 Deadline 을 넘으면 경고 표시).
  MS Project 의 *기준선*(처음 계획의 사본)은 지금 넣지 않음 — 1인 툴에는 무겁다.
- 파생값: `slackDays` = 마감 − 끝낼 예정(일). 음수면 「계획이 마감을 넘음」. 파트·컷·「파트 없음」 묶음 모두에 있음.
- 유저 결정: 입력은 **시작 + 끝 날짜**. 「오늘」은 계획 시작 전인 일을 숨기지 않고 `beforePlan`(흐리게 + 「12/7 시작」),
  마감 지남/4일 안이면 계획과 상관없이 보임. **계획이 시작된 일**(`planStarted`, 계획 끝이 지났어도)도 「오늘」에 들어감.
- 저장은 시작·끝 두 칸(각각 비워도 됨). 「시작만」, 「시작 + 작업일 수」는 이 두 칸으로 다 표현된다
  (작업일 수 입력 → 화면이 끝 날짜로 바꿔 저장). 그래서 무엇을 입력받을지는 화면의 결정으로 남는다.

## 하루 몇 컷 (`Pace`, `paceOf(group)`)

- 남은 컷 = 아직 손에 있는 컷(받음 · 작업중 · 리테이크). 제출·완료는 뺌.
- 남은 날 = **오늘(또는 내 계획 시작이 더 뒤면 그날)부터 끝나는 날까지, 양 끝 포함**, 쉬는 요일 뺌.
  끝나는 날 = 설정 `pace_end`. 날짜 경계는 하루 시작 설정을 따름.
- 쉬는 날 = 쉬는 요일(기본 토·일) + 쉬는 날 표(`addDaysOff(시작, end:, note:)`, 단일 날짜·기간).
  계획 시작이 쉬는 날이면 다음 작업일부터 셈. 끝까지 쉬는 날뿐이면 남은 날 0 · `behind`.
- `perDay` = 남은 컷 ÷ 남은 날. 끝이 지났으면 남은 날 0 · `behind` · 오늘 몫 = 남은 컷 전부.
- 오늘 몫 `today` = `perDay`, 단 계획 시작 전이거나 오늘이 쉬는 요일이면 0.
- `today()` 의 `cutsToday` = 아직 손에 있는 모든 묶음의 오늘 몫 합(목록에 안 보이는 묶음 포함) — 겹치는 파트가 더해짐.
- `PartStageRow` 의 고정 필드가 아니라 `paceOf(group)` 로 계산 — 「지금」과 설정에 따라 바뀌는 값이라서.

## 보기용 쿼리 (`CatalogueStore`)

- `taskRows({workId})` — 살아 있는 작업 한 줄씩(작품·화·파트·공정·컷 순). 단가·길이·테이크·유료
  리테이크·타이머 시간을 쿼리 한 번에 계산(N+1 없음).
- `partGroups({workId})` (= `PartStageRow`) — 스케줄 단위 = **파트 × 공정**. 파트 없는 컷은 화 × 공정마다
  「파트 없음」 묶음 하나(`GroupKind.noPart`, 마감 = 그 컷들 중 가장 이른 것), 콘티 작업은 혼자서 한 단위.
  **마감 순**(마감 없음은 끝). 상태·작품 거르기는 UI.
  - 상태별 컷 수 `counts`, `handed/total`(제출·완료 / 전체), 계산된 상태 `status`,
    마감(파트 마감 / 혼자면 그 작업 마감), 착수(가장 이른 받은 날), 금액 `pay` + 미정 `unpriced`
    (작품 하나 = 통화 하나), 작업시간 `worked`.
  - 파트 상태 계산(시안 가정): 모두 완료 → 완료 · 리테이크 하나라도 → 리테이크 ·
    모두 제출 이상 → 제출 · 모두 받음 → 받음 · 그 밖 → 작업중.
  - 컷 줄 `TaskRow`: 컷 번호/콘티 라벨 `unitLabel`, 길이, 상태, 테이크(T2…), 마감 `dueAt` + 파트에서
    왔는지 `dueFromPart`(반대로 덮었는지 `dueOverridden`), 금액 `pay`(null=미정), 작업시간 `worked`.
- `today({horizonDays = 4})` — 아직 손에 있는 단위 중 남은 날 ≤ 4(지난 것 포함)이거나
  작업중·리테이크이거나 계획 시작일이 온 것. 항목마다 `pace`, `beforePlan`, `planStarted`. 남은 날 순(마감 없음은 끝), 같으면 리테이크 → 작업중 → 받음.
  `late` = 지난 단위 수 + 자기 마감이 지난 컷 수. 날짜 경계는 하루 시작 설정을 따름.

### 비용 측정 (2026-11-27, 클라우드 컨테이너 · 테스트 모드)

- 작업 19,200건(작품 20 × 화 5 × 파트 4 × 컷 12 × 공정 4) · 묶음 1,600개: `partGroups` ≈ 150ms, 그중 SQL ≈ 90ms.
  실행 계획은 전부 인덱스 조회 + 정렬용 임시 B-tree 하나.
- 상세에만 필요한 값(테이크 · 유료 리테이크 · 작업시간 하위 쿼리)을 빼도 SQL ≈ 96ms로 그대로
  ⇒ **목록용 / 상세용 쿼리로 나눠도 얻는 게 없음.** 비용은 행 수(쌓이는 완료 이력)에 비례.
- 줄이는 길: ① 보기 목록에서 오래된 완료분을 빼는 범위 조건(예: 완료 후 N일 지난 묶음 제외)
  ② 읽기를 백그라운드 isolate 로(보고 13 제안). 실사용 규모(손에 든 일 수백 건)에선 둘 다 아직 불필요.

## 쓰기 API 메모

- 일괄 상태 변경 `setStatusMany(작업 id 목록, 상태)` — 한 트랜잭션, 하나라도 실패하면 전부 그대로.
  화면은 「선택(여러 개) → 동작」 방식(유저 결정).

## 나중에 (기록만, 구현 안 함)

- **구속 계약** — 컷당이 아니라 달마다 정해진 금액을 받는 일. 유저: 알아만 두고 금융 쪽은 아직 키우지 않음.
  넣게 되면 작품(또는 계약)에 「월정액」을 두고 월 합계에 더하는 식이 될 것.

## 남은 질문

(없음)

정해진 것(위험): 「계획 끝 > 마감」(`slackDays < 0`)만 위험으로 본다. 속도 예측은 나중에.

정해진 것(하루 몇 컷): 남은 날은 계획 시작일(오늘보다 뒤면)부터 · 끝은 내 계획 끝(없으면 마감) ·
쉬는 요일 기본 토·일 + 쉬는 날 표 · 계획이 시작된 일은 끝이 지나도 「오늘」에 남김.
