# 데이터 모델

> 데이터 담당. 유저 답 3차까지 반영 → 스키마 v4 + 보기용 쿼리. **❓ = 아직 유저 답이 필요한 것.**

## 저장 원칙 (기술 결정)

- 시각은 **UTC epoch 밀리초 INTEGER**. 마감도 날짜가 아니라 시각으로 저장(화면이 날짜로 보여 줌).
- 돈은 **정수 최소 단위**(엔·원 모두 소수 없음). 통화는 작품에 3글자 코드, 기본 `JPY`.
- 경과 시간은 저장하지 않는다 — 타이머는 시작·정지 시각만, 경과는 계산.
- 스키마 버전 = `PRAGMA user_version`. 앞으로만, 한 단계 = 한 트랜잭션, 더 새 파일은 거부.
- 삭제는 **소프트 삭제**(`archived_at`).

## 설정 (`settings` 테이블, 키 하나 = 행 하나, 없으면 기본값)

| 키 | 뜻 | 기본 |
|---|---|---|
| `seconds_rounding` | 초당 단가에서 컷 길이를 초로 맞추는 방식 | `nearest`(반올림) |
| `day_start_minutes` | 하루가 시작하는 시각(자정 뒤 분) | `0`(자정) |

**초당 단가 반올림은 「길이」에 적용한다** — 길이를 먼저 정수 초로 맞추고 단가를 곱한다.
- `nearest` 반올림: 3.5초 → 4초, 3.49초 → 3초
- `up` 올림: 3.01초 → 4초
- `down` 버림: 3.99초 → 3초
- `exact` 비례: 3.5초 그대로 → 금액만 엔 단위로 반올림
(유저: 실제 업계 방식은 나중에 확인 — 그래서 옵션.)

## 구조 (v4)

```
공정 프리셋 stage_presets → stage_preset_items (편집 가능, 기본 프리셋 하나 「기본」)
   새 작품을 만들 때 프리셋을 복사 → 이후 프리셋을 고쳐도 기존 작품은 안 바뀜

거래처 clients (마감일, NULL=말일)
 └< 작품 works (통화, 기본 JPY)
     ├< 공정 목록 work_stages (작품마다 편집 가능, 순서 있음 — 만들 때 프리셋에서 복사)
     └< 화수 episodes
         ├< 화수별 기본 단가 episode_rates (공정마다: 고정액 / 초당)
         ├< 담당 파트 parts (라벨 「B」, 예정 컷 수 — 컷 목록보다 먼저 적을 수 있음)
         │    └< 파트 × 공정 마감 part_stage_dues
         ├< 컷 cuts (번호 텍스트 + 자동 정렬 키, 길이 length_ms, 소속 파트 part_id — 없어도 됨)
         └< 콘티 storyboards (컷이 아닌 하나의 단위)

내 작업 tasks = (공정 1개) × (컷 1개 또는 콘티 1개)
   상태: 받음 → 작업중 → 제출 → 리테이크 → 완료
   마감: 작업에 직접 넣은 마감 → 없으면 그 컷이 속한 파트의 그 공정 마감 (뷰 task_dues)
   단가 덮어쓰기(rate_unit, rate_amount)
 ├< 리테이크 retakes (테이크 2, 3, … 제한 없음, 기본 무료, 건별 유료 + 금액)
 └< 작업시간 work_intervals.task_id (비워도 됨, 타이머는 한 번에 하나)
```

처음 기본 프리셋 10개: 콘티 · 콘티 체크 · LO · LO 연출 수정 · LO 작감 수정 · LO 총작감 수정 ·
원화 · 원화 연출 수정 · 원화 작감 수정 · 원화 총작감 수정.
유저 역할(원화맨 / 작감 / 연출)은 따로 저장하지 않고, **어느 공정에 내 작업이 있는가**로 드러난다.

### 담당 파트 흐름

1. 파트를 만든다 — 「작품 A · #05 · B파트 · 11컷」(컷 목록은 나중이어도 됨).
2. 파트에 공정 마감을 넣는다 — 「B파트 LO 12/10까지」.
3. 컷이 들어오면 파트에 넣고 `addTasksForPart` 로 그 공정의 작업을 한 번에 만든다.
4. 컷 작업은 기본으로 파트 마감을 따른다. 파트 마감을 옮기면 따라 움직인다.
   컷에 직접 마감을 넣으면 그 컷만 따로 간다(옵션 — 세세한 수정).

### 단가 · 합계

- 단가 방식은 작품에 따라 **공정별 컷당**(기본) 또는 **공정별 초당**. 한 컷에 둘이 더해지지는 않는다.
  공정별 기본 금액은 앱이 박아 두지 않는다(유저가 화수마다 입력).
- 작업의 단가 = 작업에 직접 넣은 단가 → 없으면 그 화수의 그 공정 기본 단가 → 없으면 미정.
- 작업 금액 = 단가 금액 + 유료 리테이크 금액 합.
- **월 합계 = 완료일 기준, 통화별 따로(환산 없음).** 거래처 마감일로 기간을 자른다
  (20일 마감이면 전월 21일 ~ 당월 20일, 거래처 없으면 달력 한 달). 단가·길이가 없어
  계산 못 한 작업은 「미정 n건」으로 따로 센다.
- 청구·입금 테이블은 없다(유저: 금융 앱 아님, 합계만).

## 보기용 쿼리 (`CatalogueStore`)

- `taskRows({workId})` — 살아 있는 작업 한 줄씩(작품·화·파트·공정·컷 순). 단가·길이·테이크·유료
  리테이크·타이머 시간을 쿼리 한 번에 계산(N+1 없음).
- `partGroups({workId})` (= `PartStageRow`) — 스케줄 단위 = **파트 × 공정**. 파트 없는 컷은 화 × 공정마다
  「파트 없음」 묶음 하나(`GroupKind.noPart`, 마감 = 그 컷들 중 가장 이른 것), 콘티 작업은 혼자서 한 단위.
  **마감 순**(마감 없음은 끝). 상태·작품 거르기는 UI.
  - 상태별 컷 수 `counts`, `handed/total`(제출·완료 / 전체), 계산된 상태 `status`,
    마감(파트 마감 / 혼자면 그 작업 마감), 착수(가장 이른 받은 날), 금액 `pay` + 미정 `unpriced`
    (작품 하나 = 통화 하나), 작업시간 `worked`.
  - 파트 상태 계산(시안 가정): 모두 완료 → 완료 · 리테이크 하나라도 → 리테이크 ·
    모두 제출 이상 → 제출 · 모두 받음 → 받음 · 그 밖 → 작업중.
  - 컷 줄 `TaskRow`: 컷 번호/콘티 라벨 `unitLabel`, 길이, 상태, 테이크(T2…), 마감 `dueAt` + 파트에서
    왔는지 `dueFromPart`(반대로 덮었는지 `dueOverridden`), 금액 `pay`(null=미정), 작업시간 `worked`.
- `today({horizonDays = 4})` — 아직 손에 있는 단위 중 남은 날 ≤ 4(지난 것 포함)이거나
  작업중·리테이크인 것. 남은 날 순(마감 없음은 끝), 같으면 리테이크 → 작업중 → 받음.
  `late` = 지난 단위 수 + 자기 마감이 지난 컷 수. 날짜 경계는 하루 시작 설정을 따름.

## 나중에 (기록만, 구현 안 함)

- **구속 계약** — 컷당이 아니라 달마다 정해진 금액을 받는 일. 유저: 알아만 두고 금융 쪽은 아직 키우지 않음.
  넣게 되면 작품(또는 계약)에 「월정액」을 두고 월 합계에 더하는 식이 될 것.

## 남은 질문

1. **공정 프리셋을 여러 개 둘까?** (회사별·역할별 — 「A사용」「작감용」) — 구조는 여러 개를 받을 수 있게
   해 두었고 지금은 「기본」 하나만 씀. 추천: 하나로 시작, 필요하면 추가.
2. **작품의 단가 방식(컷당/초당)을 작품에 한 번 정해 둘까?** 지금은 화수 × 공정마다 방식을 고름 —
   추천: 작품에 기본 방식을 두고 화수 단가 입력 때 그 방식이 미리 선택되게(화면 편의, 데이터는 지금대로).
3. **파트가 화를 넘나드나?** 지금은 파트 = 한 화 안의 컷 묶음. 「#05~#06 B파트」처럼 여러 화에
   걸치는 경우가 있으면 구조를 바꿔야 함 — 추천: 한 화 안(지금 구현).
4. **한 컷이 두 파트에 속할 수 있나?** — 추천: 아니오, 파트 하나 또는 없음(지금 구현).
5. **예정 컷 수와 실제 컷 수가 다르면?** 예정 11컷인데 컷을 12개 넣었을 때 — 추천: 막지 않고
   화면에 「11/12」처럼 차이만 보여 줌(지금 구현: 막지 않음).
6. **단가도 파트마다 다를 수 있나?** 지금은 화수 × 공정 기본 단가만 있음 — 추천: 화수 단위 유지.
7. **파트 전체의 상태를 한 번에 바꾸고 싶나?** (B파트 LO 전부 「제출」) — 데이터는 컷 작업마다
   저장하므로 한 번에 바꾸는 기능은 화면 쪽에서 가능. 필요한지 여부만.
8. **설정은 앱 전체에 하나?** 초당 반올림 방식이 작품·회사마다 다를 수 있나 — 추천: 앱 전체 하나
   (지금 구현), 필요하면 작품별로 덮어쓰기 추가.
